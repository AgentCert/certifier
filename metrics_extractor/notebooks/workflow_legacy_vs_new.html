TTD Aggregation Workflow — Legacy vs New

Side-by-side block diagram: what each pipeline does at every stage, where they diverge, and what the new pipeline preserves that the legacy one drops on the floor.

Legacy — validate_ttd_logic.ipynb New — metric_scorecard_pipeline.ipynb

Legacy workflow

validate_ttd_logic.ipynb · 3 stages · stops at category
Input Per-run dict: {run_id → {category → {fault → ttd}}} + sla[fault]. ttd may be None (miss).
↓
Step 1 · Normalize per fault normalize_ttd_with_fault_sla(fault, ttd, sla) → score in [0, 1] using piecewise SLA-aware curve.
ttd = None → score 0 sla = None → score = None (dropped)
↓
Step 2 · Per-run-per-category mean For each (run, category): take mean(fault_scores) across all faults in that category. Scores of None are skipped. 2 faults in a category → each fault contributes 50% of the run's category number
↓
Step 3 · Per-category overall (across runs) For each category: mean / median / stdev / min / max / count_runs of the per-run means. Headline = mean of per-run means.
↓
Output One row per category with {mean, median, stdev, min, max, count_runs}.
No cumulative / agent-level number No quality flags No detection_rate / sla_compliance
What gets dropped
  • NO_SLA obs are silently filtered out (no audit trail)
  • A run that misses every fault in a category contributes nothing (it's excluded), so miss rate is invisible
  • No way to tell why a low score is low: is it slow detect? lots of misses? lots of breaches? legacy mean averages them all into one number

New workflow

metric_scorecard_pipeline.ipynb · 5 stages · 4 grains of output
Input Same per-run dict + SLA. Plus a metric_name param so the same pipeline runs on TTD, TTM, etc.
↓
§1 · Classify every observation Each (run, category, sub_fault) becomes one Observation with a status: VALID MISSING (ttd = None) INVALID_ZERO NO_SLA Misses stay in the pool with score 0; NO_SLA stays in the dataframe but is excluded from aggregation (audit trail kept).
↓
§2 · Normalize Same piecewise SLA-aware curve as legacy: within SLA → 1 − 0.85·ratio, breach → max(0, 0.15 − 0.3·(ratio−1)). One score per obs, never None.
↓
§3 · Sub-fault grain Pool all obs of a sub-fault. Confidence tiered by n: n<3 INSUFFICIENT n<5 LOW (mean) n<20 MEDIUM (0.7·median + 0.3·p5) n≥20 HIGH (0.5·median + 0.3·p5 + 0.2·p1)
Each obs gets one vote — rare sub-faults aren't drowned by frequent ones.
↓
§4 · Category grain Pool all obs across sub-faults in the category. category_score = median(pool). Also emits detection_rate + sla_compliance.
↓
§5 · Cumulative (agent-level) Pool every obs across all categories. cumulative_score = median(pool). Diagnostics collapsed into quality_flags: skewed_distribution |mean−median| > 0.15 mixed_category_health |mean(cat_scores)−median| > 0.15 N_obs_excluded_no_sla
↓
Output Four dataframes (obs → sub-fault → category → cumulative). One headline number plus the diagnostics needed to know whether to trust it.

Stage-by-stage differences

Concern Legacy New
Atomic unit Per-fault score, may be None Observation with explicit status — never None
Missing TTD Score = 0, but the obs is averaged inside per-run mean — its weight depends on how many other faults the run had Score = 0, kept as one vote in the pool; detection_rate separately reports miss rate
NO_SLA Silently dropped — no record kept Kept in observation dataframe with status=NO_SLA; excluded from aggregation; counted in N_obs_excluded_no_sla flag
Aggregation grain Per-run — each run produces one number per category, then averaged across runs Per-obs — every observation is one vote in the pool, then median taken
Headline statistic mean of per-run category means median of pooled obs scores
Output grains Category only Observation · sub-fault · category · cumulative (all four available)
Confidence signal None — count_runs is reported but no tier Per-sub-fault tier: INSUFFICIENT / LOW / MEDIUM / HIGH; weighting changes with tier
Detection / breach split Both folded into the score — caller can't tell whether agent is slow or missing Separate detection_rate and sla_compliance at every grain
Quality flags None skewed_distribution · mixed_category_health · N_obs_excluded_no_sla
Cumulative number Not produced cumulative_score at agent grain
Metric-agnostic TTD-specific naming throughout metric_name param — same pipeline runs on TTD, TTM, or anything else with an SLA

What the new shape gives the downstream consumer

Question consumer asks Legacy answer New answer
"Is the agent healthy overall?" Can't say — no cumulative number cumulative_score + flags
"Is the agent missing faults or just slow?" Conflated in the mean detection_rate vs sla_compliance tell them apart
"Are the categories evenly healthy?" Eyeball per-category means side by side mixed_category_health flag fires automatically
"Is the headline trustworthy?" No diagnostic — stdev is the only hint quality_flags = ['none'] ⇒ yes; any flag ⇒ look deeper
"How much data backed this?" count_runs, but no minimum-n warning n_attempted + confidence tier at sub-fault grain
"Can we score TTM the same way?" No — TTD-specific code paths Yes — pass metric_name='ttm'
