Certifier

Goal: bring down the GPT-4 bill in fault_analyzer/ and metrics_extractor/.

# Difficulty Item Why How Sources
1 Easy Check if prompt caching is actually working Repeated instructions and schema text can dominate token spend across large runs. Caching lowers both cost and latency when the shared prompt context stays stable. Keep the reusable context consistent across requests and place variable trace content after that stable context. In batch workflows, maximize reuse of the same static prompt prefix and track cache-hit behavior. OpenAI Prompt Caching Anthropic Prompt Caching Azure OpenAI caching
2 Easy XGrammar / structured outputs Unstructured model output creates avoidable parsing failures, retries, and quality drift in downstream pipelines. Use schema-constrained generation to keep output aligned with the expected structure, and use Pydantic as the typed contract for runtime validation. The combination improves reliability, reduces rework, and stabilizes batch processing. XGrammar (arXiv 2411.15100) OpenAI Structured Outputs vLLM structured outputs
3 Medium Trim the prompt and batch 8–10 items per call Sending repeated instructions for every small unit of work drives unnecessary token and request overhead. Reduce prompt verbosity and process items in grouped batches so shared context is paid once per batch. Use asynchronous batch processing for non-interactive certification workloads. OpenAI Batch API Azure OpenAI Batch FrugalGPT (arXiv 2305.05176)
4 Medium Follow the OTel GenAI span spec Standard telemetry already contains deterministic signals for usage, timing, and tool activity. Re-extracting these with an LLM adds cost and ambiguity. Align instrumentation with OTel GenAI conventions and treat structured span attributes as the first source of truth. Use LLM reasoning only for the remaining ambiguous context. OTel GenAI Spans spec OTel GenAI semconv Langfuse OTel ingestion
5 Medium Use a cheaper model for classification Many bucketing and screening decisions are routine classification tasks that do not require the most expensive model tier. Use a routed model strategy: start with a lower-cost model and escalate only uncertain cases to a stronger model. Calibrate the routing policy against quality benchmarks. RouteLLM (arXiv 2406.18665) Hybrid LLM (arXiv 2404.14618) Claude Haiku 4.5
6 Medium Prompt compression + caching + constrained decoding (stacked) Individual optimizations usually provide moderate gains, but token-heavy pipelines benefit most from a combined strategy. Apply context compression for variable payloads, prompt caching for repeated context, and structured decoding for stable outputs. Evaluate quality and cost together to keep optimization safe. Provence (arXiv 2501.16214) LLMLingua-2 (arXiv 2403.12968) 500xCompressor (arXiv 2408.03094)
7 Hard Hybrid GraphRAG over a fault-pattern graph Flat prompt context scales poorly as fault taxonomies and trace volume grow, leading to rising cost and lower retrieval focus. Introduce graph-aware retrieval so each analysis step pulls only the most relevant fault subgraph and evidence paths. Keep knowledge updates incremental and evaluation benchmark-driven. Product surface

Make Certifier usable by teams who don't author code — agent onboarding, prompt and metric authoring, and certificate runs all from a UI.

# Difficulty Item Why How Sources
1 Hard New Build a Certifier UI: onboard agents, author prompts & metrics dynamically, trigger certification runs Today every new agent or metric requires a code change in fault_analyzer/, metrics_extractor/, or the prompt configs. That blocks non-engineers from running their own certifications and slows iteration on prompts and metrics. Web UI where users (1) onboard an agent (name, model, trace source); (2) an auto-bootstrap pipeline runs to generate / refresh the agent-specific prompts — hypothesis prompts, narrative prompts, fault-bucketing prompts, metric-extraction prompts, and any other prompts the pipeline depends on; (3) the user reviews and edits prompts and metric definitions in a form/JSON editor with live validation; (4) save as a versioned bundle; (5) trigger a certification run that pulls the bundle and executes the existing pipeline. Persist bundles in MongoDB next to the existing collections; reuse the FastAPI endpoints in app.py as the backend.
