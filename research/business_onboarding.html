·The two ideas behind this UI

① Business questions, not statistics

The SME picks from 9 universal questions (“typical value”, “breach rate”, “tail risk”…). Each is just a friendly alias for one of H01–H09 in the engine.

② Domain Pack = one JSON

The wizard’s output is a versioned Domain Pack (metrics + thresholds + chosen questions). The engine is untouched; only the pack changes per domain.

③ New stat test = backend plugin

Only when the domain needs a genuinely new statistical method does a developer register a StatPlugin. Once registered it appears in everyone’s palette.

def run(data, params):
    """Implements the StatPlugin interface."""
    revenue = data["revenue"]
    cogs    = data["cogs"]
    margin  = (revenue - cogs) / revenue
    ci      = bootstrap_ci(margin, alpha=params["alpha"])
    return UnitEconomicsResult(
        margin_iqm = iqm(margin),
        ci_lower   = ci.low,
        ci_upper   = ci.high,
    )

HWhat changes per domain — and what doesn’t

✅ What changes

  • The Domain Pack JSON (metrics, units, thresholds, picked questions)
  • The narrative templates for the cert report (“speaks FinOps”)
  • The data source connector (Mongo / REST / file drop)

🔒 What does NOT change

  • The 16 stat-test plugins in scripts/statistical_tests/
  • The 9 hypothesis runners (H01–H09)
  • The Pydantic result schema
  • The cert builder pipeline

🛠 When code is needed

  • Only if the domain needs a genuinely new statistical method (e.g. unit-economics margin, cohort retention curves).
  • Then: register a plugin via the catalogue (section D) → it shows up in the designer’s palette & the wizard’s test list automatically.
