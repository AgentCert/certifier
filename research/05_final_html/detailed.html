Approach 1 — Deterministic First, LLM Last (OTel + Drain3 + Regex Cascade)

60–80% Phase 0 calls · 40% Phase 1
Effort: 2–3 days Risk: Very low Phase 0 + Phase 1

Why this works

Litmus and Chaos Mesh already emit OpenTelemetry attributes on every event — k8s.event.reason, chaosUID, experimentName, phase, start_time, end_time. These are the lifecycle bucket labels you're paying GPT-4 to infer. Langfuse persists them. Both AWS CloudWatch Logs Anomaly Detection and UK AISI's Inspect AI ship a pattern: deterministic match()/regex first, LLM only on the residue. Drain3 / LILAC and LogParser-LLM show 5–20× compression on log templates with zero accuracy loss.

Concrete code changes

  1. Add fault_analyzer/preprocessor.py. Walks the raw trace, lifts OTel attributes into a pre_bucket: Dict[chaosUID, BucketStub]. Spans already labelled by Litmus/Chaos Mesh skip the LLM entirely.
  2. Run Drain3 over span names + log messages → template IDs. Identical templates collapse to one exemplar before any LLM call.
  3. In metrics_extractor/scripts/metrics_extractor_from_trace.py: timestamps (start_time, end_time, TTD, TTR) come directly from OTel attributes — drop the LLM "timestamp validation" call. LLM only handles qualitative fields (root cause narrative, severity rationale).
  4. Add a calibration gate: if pre_bucket coverage > threshold (say, 80% of events labelled deterministically), skip the entire Phase 0 LLM call for that trace and only invoke for unlabelled residue.
# fault_analyzer/preprocessor.py (sketch)
from drain3 import TemplateMiner
from drain3.template_miner_config import TemplateMinerConfig

class TracePreprocessor:
    def __init__(self):
        cfg = TemplateMinerConfig(); cfg.load_from_dict({"DRAIN": {"sim_th": 0.4}})
        self.miner = TemplateMiner(config=cfg)

    def lift_otel(self, span):
        attrs = span.get("attributes", {})
        return {
            "chaos_uid": attrs.get("chaosUID"),
            "experiment": attrs.get("experimentName"),
            "phase": attrs.get("phase"),           # injected | running | recovered
            "start_ns": span["startTimeUnixNano"],
            "end_ns":   span.get("endTimeUnixNano"),
        }

    def to_buckets(self, trace):
        buckets, residue = {}, []
        for s in trace["spans"]:
            stub = self.lift_otel(s)
            if stub["chaos_uid"] and stub["phase"]:
                buckets.setdefault(stub["chaos_uid"], []).append(s)
            else:
                # template-collapse before LLM
                tpl = self.miner.add_log_message(s.get("name","")).cluster_id
                residue.append((tpl, s))
        return buckets, residue   # only `residue` is sent to the LLM

Expected savings

Empirical estimates from chaos-experiment traces: 60–80% of events are deterministically classifiable from OTel attributes; Drain3 collapses the residue another 5–20×. Phase 1 timestamp + ID extraction (currently 1–2 calls per bucket) drops to zero.

Reinforced by K8s/Langfuse research: the OpenTelemetry GenAI semantic conventions (gen_ai.usage.input_tokens, gen_ai.usage.output_tokens, gen_ai.usage.cached_input_tokens, gen_ai.request.model, gen_ai.response.finish_reasons, gen_ai.server.time_to_first_token, etc.) are already populated by Langfuse, Traceloop OpenLLMetry, Arize Phoenix, Sentry, and PostHog. AgentCert is currently spending GPT-4 calls to infer values that are sitting in the span as structured attributes. K8sGPT, HolmesGPT, Komodor Klaudia, Dynatrace Davis CoPilot, and Grafana Sift all follow the same pattern: deterministic correlation first, LLM only for summarization. See research/03_industry/04-k8s-langfuse-finops-landscape.md for the full gen_ai.* attribute table and reusable prompt templates.

Approach 2 — Cascade Router (Cheap-First, Frontier-on-Disagreement)

50–70% $
Effort: 1 week Risk: Medium All phases

Why this works

Uber's GenAI Gateway, GitHub Copilot multi-model selection, Gemini Flash→Pro, and Microsoft AutoGen all centralize on the same pattern: route to a cheap model first, escalate to a flagship only when needed. FrugalGPT (arxiv 2305.05176) and RouteLLM (arxiv 2406.18665) formalize the decision rule. Anthropic's "Panel of Diverse Models" finding (3 small judges beat single GPT-4 at ~1/7 cost) makes the same point for evaluators. Haiku is ~1/7 of Sonnet; Gemini Flash is ~1/10 of Pro.

Concrete code changes

  1. Wrap utils/azure_openai_util.py:AzureLLMClient in a RoutingLLMClient(tier="cheap"|"flagship"|"reasoning").
  2. Phase 0 bucketing → Haiku / Phi-3-mini / Gemini Flash; Phase 1 quantitative → Haiku; Phase 1 qualitative → Sonnet only if Haiku log-prob confidence < 0.85.
  3. Cheap model returns {label, confidence_logprob}. Escalation triggers: (a) confidence < 0.85, (b) schema-validation failure, (c) explicit reasoning_required flag.
  4. Add cost_per_call to the metrics_extractor output object for closed-loop telemetry (same pattern New Relic AI Monitoring ships).
# utils/routing_llm_client.py (sketch)
TIER_TO_MODEL = {
    "cheap":     {"deployment": "haiku-4.5",  "max_cost": 0.0001},
    "flagship":  {"deployment": "sonnet-4.6", "max_cost": 0.0030},
    "reasoning": {"deployment": "opus-4.7",   "max_cost": 0.0150},
}

class RoutingLLMClient:
    def chat(self, prompt, tier="cheap", escalation_threshold=0.85):
        out = self._call(TIER_TO_MODEL[tier], prompt, logprobs=True)
        if out.confidence < escalation_threshold and tier != "reasoning":
            self.metrics.escalations[tier] += 1
            return self.chat(prompt, tier="flagship" if tier == "cheap" else "reasoning")
        return out

Approach 3 — Prompt Caching + Batch API + Constrained JSON

85% input · 50% nightly
Effort: 1–2 days Risk: Very low Phase 0 + 1 + 2

Why this works

Anthropic prompt-caching: cache reads cost 10% of base price, with reported 90% cost / 85% latency reduction on cached prefixes. OpenAI Batch API: 50% discount on Chat Completions with a 24h SLA. XGrammar (arxiv 2411.15100) and SGLang (arxiv 2312.07104) constrained decoding eliminate JSON-retry waste (Outlines reports 20–80% output-token reduction). The existing fault_pruning + cache_enabled flags in AgentCert are already implemented — just disabled.

Concrete code changes

  1. Flip fault_pruning: true and cache_enabled: true in fault_analyzer/config/*.yaml. Zero-line change, measured 84% reduction on faults block and 50% on system prompt.
  2. Restructure all Phase 0/1 prompts so the fixed prefix (system, schema, few-shots) comes first. Mark with cache_control: {type:"ephemeral"} (Anthropic) or use Azure OpenAI's cached_tokens annotation.
  3. Phase 2 aggregation + Phase 3 narrative builders that run per-run (not per-request) → submit as OpenAI Batch jobs. Wrap cert_builder/run_aggregation_and_certification_pipeline.py to write a .jsonl and submit to /v1/batches.
  4. Replace JSON parsing with Outlines / XGrammar / SGLang constrained decoding. Eliminates the retry loop on malformed JSON.
# cert_builder/batch_submit.py (sketch)
import json, openai

def submit_batch(prompts, model="gpt-4o-mini"):
    with open("/tmp/batch.jsonl", "w") as f:
        for i, p in enumerate(prompts):
            f.write(json.dumps({
                "custom_id": f"req-{i}",
                "method": "POST", "url": "/v1/chat/completions",
                "body": {"model": model, "messages": p, "response_format": {"type":"json_object"}},
            }) + "\n")
    file = openai.files.create(file=open("/tmp/batch.jsonl","rb"), purpose="batch")
    return openai.batches.create(input_file_id=file.id,
        endpoint="/v1/chat/completions", completion_window="24h")
# 50% off — perfect for nightly Phase 2/3.

Approach 4 — Merge Quant+Qual + Chain-of-Draft + ChainPoll Early-Stop

40% calls · 90% completion
Effort: 1 week Risk: Medium Phase 1 + Phase 2

Why this works

Phase 1 currently sends the same 6 spans to GPT-4 twice — once for quantitative, once for qualitative. Merging halves Phase 1 calls. Chain-of-Draft (Zoom Communications, arxiv 2502.18600) shows reasoning can be expressed in ≤5-word drafts at 7.6% of CoT token count with equal accuracy. Galileo ChainPoll: instead of fixed k=5 self-consistency samples, stop polling once 3-of-5 agree. Batch Prompting (arxiv 2301.08721) coalesces N inputs into one call for ~5× reduction.

Concrete code changes

  1. In metrics_extractor/scripts/metrics_extractor_from_trace.py: merge quantitative_batch_extractor and qualitative_batch_extractor into one prompt that emits {"quant": {...}, "qual": {...}}.
  2. In metrics_extractor/scripts/combined_judge.py: replace any multi-step CoT with Chain-of-Draft — "think in ≤5-word drafts before answering."
  3. In aggregator/: add early-stop ChainPoll to the LLM Council. Run k=5 cheap judges in parallel; if first 3 agree, drop calls 4 and 5. Only escalate to meta-judge on disagreement.
  4. Batch 3–5 buckets per prompt where they share the same fault label (Batch Prompting).

SCHEMA = {

PROMPT = """Analyze the bucket of {n} spans. Output JSON matching SCHEMA.

Approach 5 — Distilled Small-Model Extractor + NLI Verifier (Reimplementation Path)

90%+ steady-state
Effort: 1–3 months Risk: High Full reimplementation

Why this works

Every shipped Phase-1 output is already labelled training data. AWS Bedrock Model Distillation (Dec 2024): teacher → student → 75% cheaper, 500% faster, <2% accuracy delta. Meta's Self-Taught Evaluator (arxiv 2408.02666): a Llama-3-70B judge trained on synthetic preferences matches GPT-4 on RewardBench with no human labels. Patronus Lynx-8B beats Claude-3-Sonnet by 8.6% on HaluBench at near-zero per-token cost. Vectara HHEM-2.1-Open: T5-class NLI runs on CPU and replaces GPT-4 for claim verification.

Concrete code changes (phased)

  1. Now: log every Phase 0/1 input + GPT-4 output to a distillation_corpus/ collection (already half-done in utils/mongo_client.py).
  2. Month 1: fine-tune Phi-3-mini / Mistral-7B on the bucketing task with LoRA + 4-bit QLoRA. Serve via vLLM/TGI on a single A10G. Target ≥ GPT-4 accuracy on the golden set.
  3. Month 2: replace LLM-Council qualitative judges in aggregator/ with Vectara HHEM-2.1-Open NLI for atomic-claim verification. Flagship LLM only on the meta-synthesis step.
  4. Month 3: retire extraction_model GPT-4 calls in configs/configs.json. Keep reasoning_model only for Phase 3 final narrative.
Caveat: distillation is irreversible cost win but adds training-infra ops burden (GPU, vLLM, eval harness). Don't start until Approaches 1–4 have made the per-call cost acceptable and you have ≥10K labelled traces.

Recommended roadmap

  1. Week 1 — Approach 3: flip the two flags, add prompt-caching control headers, move Phase 2/3 to Batch API, swap JSON parsing for XGrammar. No model change, no calibration risk.
  2. Week 2–3 — Approach 1: ship fault_analyzer/preprocessor.py with OTel-attribute lift + Drain3 template collapse. LLM remains the fallback for unlabelled residue.
  3. Month 1 — Approach 4: merge quant/qual passes; add Chain-of-Draft prompt; add ChainPoll early-stop in aggregator. Requires a golden-set regression harness (10–50 hand-labelled buckets).
  4. Month 1–2 — Approach 2: introduce RoutingLLMClient once Approach-3 telemetry reveals where Haiku is sufficient.
  5. Quarter 2 — Approach 5: only after ≥10K labelled traces from Approaches 1–4 are in the distillation corpus. Fine-tune Phi-3 / Mistral-7B, swap in HHEM for NLI verification, retire extraction_model.
